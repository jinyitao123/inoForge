# Forge 默认页面交付标准

2026-09-23 起，按用户决定交付七个业务应用及各自业务设置，RISEMAP 调整为参考。本文维护任务合同、验收和证据；视觉细则见[页面精修基线](forge-page-polish-baseline.md)，规则优先级见[AGENTS](../AGENTS.md)。

## 范围与功能清单

联合核对导航、页面注册、内部跳转、列表/新建/详情/弹窗、动作、设置消费者和跨应用链。每项记录所属应用、岗位、目标结果、实现与证据；区分需求待明确、未实现、入口缺、流程断、结果/权限错误和仅缺证据。入口存在不等于完成，删除假按钮不删除需求。

按同一业务结果组织 2–5 个关联页面的批次。优先防办错、越权和丢失，再修主链、业务设置及高频工作。跨应用依赖必须走通；明确不依赖当前阻塞的其他工作可以继续。

使用[逐页合同模板](templates/forge-page-delivery.md)，写清应用/包、岗位、主单据、来源、下一步、依赖设置、主原型、布局基线、要求与验收步骤。用户需求、Forge 产品决定、外部参考、实际观察分别标注。RISEMAP 不可访问不阻塞明确的 Forge 要求；重大业务规则未知单独待决。

合同中的页面指用户界面，不强制对应 Page 元数据。先选择 object/视图、dashboard、report、component、action 或自定义 page；只有最后一种填写必需的 pageId。普通对象列表/详情与字典设置直接复用原生入口，不能为了符合清单格式新建空壳 Page。

## 样例与界面实现

| 主原型 | 参考文件（src/pages） | 用途 |
| --- | --- | --- |
| workbench | workbench.page.ts | 岗位焦点、待办和入口 |
| task_workspace | project-task-workspace.page.ts | 办理依据、动作和承接 |
| timesheet_composite | project-timesheet-cost.page.ts | 范围、填报/审核、成本与明细 |
| analysis | 上述适用分析区域 | 口径、趋势、异常与追溯 |
| configuration | 经本页合同确认的设置样例 | 维护范围、保存、生效及回读 |

样例是实现参考，不自动视为已通过。保存 Forge 设计基线的版本、视口、材料和截图，页面覆盖有数据、空态、错误、关键表单/弹窗。原生组件和共享组件按实际需求复用，不把整个公共源码串重复拼入每页，不为配置页强加指标。

本任务延续用户要求使用内置浏览器，实际展示与验证 Forge；外部参考可选。视觉验收不再要求与 RISEMAP 逐像素一致，仍检查桌面、侧栏占宽、窄屏、长文本、控件可用宽度、重叠/截断/越界、焦点和键盘路径。

## 验收维度

| 维度 | 必须证明 |
| --- | --- |
| requirements | 已采纳要求逐项有实现、步骤与结果；未实现/待决不被隐藏 |
| visual | Forge 设计基线、可读性、几何和响应式；参考对照可选 |
| interaction | 可见操作真实执行，联动、取消、提交中、防重复、失败和成功后读回 |
| business | 正常链、关键异常、金额数量状态、关联单据与下一岗位正确 |
| permissions | 不同真实角色的读/写/办理范围正确；应用可见性不能替代后端权限 |
| persistence | 涉及持久结果时，同库完整停服重启后读回一致 |
| performance | 固定版本和材料下记录冷打开、刷新、切页、请求/体积预算 |

每维分别记 pending/pass/blocked/fail，纯只读或不涉及持久写入项可在合同中说明适用范围并经复核确认，不能用不适用遮盖缺实现。真实操作、API 辅助、重启与独立复核互不替代。

业务设置必须证明“有权修改保存 → 独立会话/重启读回 → 实际业务使用 → 无权拒绝 → 在途单据正确版本”。跨应用须验证原单关联、下一岗位、旧收藏/通知链接和应用设置权限。

独立复核者可为用户或真实参与的审查者，不要求自动启动子 Agent。没有独立复核时明确未发生；不能由实施者换名字签字。

## 证据与机器门禁的迁移

当前 `tests/page-delivery-gate.mjs` 及其测试实现仍按 schemaVersion 2 检查双侧像素证据；此为历史自动门禁，尚未实现本次新准则。134 个现有 manifest 条目仍为 review_required，不能批量转通过。

下一实施工作先把门禁演进为新的 schemaVersion 3：requirements 替代 replication 必需维度，referenceEvidence 为可选；记录上述七维、Forge 基线、真实材料、角色、持久数据库与独立复核，保留被验收提交、subjectFiles 摘要及逐要求证据。旧 schemaVersion 2 记录原样保留用于解释当时结论，不补造 RISEMAP 图，也不将旧门禁 PASS 当新标准通过。

模板中的新 JSON 是拟实施契约，当前脚本尚不能作为新版本的 accepted 校验器。门禁迁移完成前可形成 Markdown 人工审查与部分证据，manifest 保持 review_required 并注明“新门禁待接入”，不能降低证据标准绕过。

受验页面/组件/对象/动作/导航/设置消费者的实际文件摘要与版本须固定。相关文件变化后重验受影响维度；未受影响证据说明复用依据。机器只验证结构、版本和可核对条件，不能替代页面美观、真实办理或业务正确性。

## 检查与持续执行

规则/文档修改检查链接和适用工具；门禁代码变化跑其单元测试与 `pnpm acceptance:page-polish`。元数据变化继续 typecheck、validate、build 和相称业务验证，持久状态使用同一持久数据库完整重启读回。

同一失败连续两次无新证据就换定位方式。完整 DOM/截图/日志留在证据附件，交接只带范围、版本、事实、未决项和下一步。阶段汇报分别说明设计、实现、验证、部署；参考资料不足不自动升级为业务阻塞，也不能变成“已完成”。
