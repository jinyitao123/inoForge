# Forge 对 RISEMAP 的实现与验证矩阵

更新于 2026-09-10，当前实现位于隔离分支 `codex/otc-purchase-payment`。顺序 OTC 过程证据见 `docs/forge-otc-sequential-ledger.md`。

本表是 Forge 当前覆盖状态的唯一汇总。其他文档中的阶段性描述若与本表冲突，以本表为准。RISEMAP 页面可进入、Forge 列表可打开或保存过截图，只能证明入口存在；只有在真实浏览器中提交表单或触发动作并核对持久结果，才记为“浏览器办理”。

## 判定口径

| 状态 | 判定 |
| --- | --- |
| 已证明 | 对应行为已实现，并完成定向 API 验收、同一 SQLite 停服重启回读和真实浏览器办理 |
| 部分证明 | 已实现一部分，或验证层级不全；缺失项在单元格内明确列出 |
| 未实现 | Forge 尚无可运行的对应业务对象或动作；导航占位不算实现 |
| 待 RISEMAP 复核 | Forge 可独立运行，但 RISEMAP 尚无同材料成功业务记录，不能声称行为一致 |

## 当前结论与执行顺序

Forge 目前不能称为完整覆盖 RISEMAP。当前顺序 OTC 主链已从项目立项推进到项目结算后的经营分析，并完成工时、多类费用、六类成本结算以及采购应付的申请、审批、实际付款和核销；这些阶段均完成相称 API、同库重启和 Forge 浏览器办理。采购入库仍不自动生成应付，付款阶段使用已存在的进项发票与应付继续验证，其余大块多数未实现。

后续以同一笔 OTC 项目为主线顺序推进：

1. 采购付款与核销已完成可追溯首版；下一步补预付款、退款、撤销付款、反核销、红冲、对账和收入确认。
2. 在出现可验证的 RISEMAP 对应入口后再补计划基线、修订和变更；甘特条与组合进度工作台需要独立前端视图能力。
3. 补齐 BOM 的图纸关联、版本替代、归档、对比及生产引用锁定。
4. 补预付款、退款、撤销付款、反核销、红冲、对账和收入确认，形成更完整的资金与财务账。
5. 主链跑通后再补委外、行政人事、报表、权限、集成、导入导出和打印等横向能力。

每一块通过验收后继续下一块；阶段报告只更新矩阵，不再把单个切片描述成完整复刻完成。
