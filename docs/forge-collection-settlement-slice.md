# Forge 开票回款与项目结算切片

更新于 2026-09-10。该切片承接已完成客户验收的 OTC 项目，覆盖验收开票、实际到账、手工分配、审核核销和项目结算。它证明 Forge 内部链路可运行，不代表已与 RISEMAP 的同材料成功结果对照一致。

## 已实现行为

- 只有已完成客户验收且项目状态为已完工的关联订单可以按剩余未开票金额开票。动作同时生成销项发票和应收账款，并回写订单、项目及项目订单关联的开票累计。
- 资金账户保存银行、支行、账号、期初余额和当前余额。登记收款会形成独立实际到账流水并增加账户余额，不会提前减少应收。
- 收款流水需手工分配到应收。待审核分配可以取消，取消后恢复流水未分配余额；审核后才更新应收、发票、订单、项目和项目订单关联的回款累计。
- 项目仅在已全额开票、全额回款、全部应收结清时允许结算。结算从已交付组装单读取并按组装单去重汇总物料成本，保存合同额、开票额、回款额、生产成本、毛利和毛利率快照，并把项目置为已结算。
- 专用工作台支持选择已完工项目和关联订单、创建并选用资金账户、验收开票、登记到账、分配、审核及项目结算。

## 验证结果

- API 基准使用 `PRJ-2026-001`：验收开票 `243200`，登记两笔到账 `100000 + 143200`，覆盖待审核分配取消、部分核销、最终结清和结算前置阻断。期初余额 `1000` 的账户结余为 `244200`，项目生产成本为 `32640.0066`，毛利为 `210559.9934`。
- 浏览器独立使用 `PRJ-2026-002`：创建 `FA-BROWSER-20260910`，开具 `INV-BROWSER-20260910-001`，登记 `CR-BROWSER-20260910-001`，审核 `CA-BROWSER-20260910-001`，生成 `PST-BROWSER-20260910`。金额为 `121600`，生产成本为 `16320.0034`，毛利为 `105279.9966`。
- 验收服务使用独立端口 `4359` 和 `.objectstack/otc-collection-settlement.sqlite`。数据库执行 `PRAGMA integrity_check` 返回 `ok`；完整停服后从同一 SQLite 重启，API 和浏览器创建记录均按原 ID、状态、金额及关联回读通过。
- 元数据门禁通过：83 个对象、1214 个字段、15 个页面、73 个动作。验收报告写入运行时目录 `.objectstack/acceptance/otc-collection-settlement-report.json`，不纳入 Git。

## RISEMAP 证据与剩余边界

RISEMAP 的收款流水页面明确展示“到账流水先手工分配到销售订单，核销前可解除关联，核销后刷新订单回款”；资金流水页面显示分配审核前不计入订单回款，并存在待分配、待审核等状态；资金账户的新建字段已观察。当前没有同材料成功开票、到账、分配、审核和项目结算记录，因此 Forge 的“客户验收后按订单剩余金额开票”与项目结算触发规则仍标为待 RISEMAP 复核。

本切片未覆盖银行流水导入与自动匹配、预收款、退款、反核销、红冲、对账、收入确认、应付付款、工时与制造费用归集、税务申报、角色权限和跨多对象动作的事务级原子回滚。项目成本目前只汇总已交付组装单的物料成本，不代表完整财务成本账。
