# Forge 采购待办池逐页原型合同

## 页面与证据

- RISEMAP 入口：`https://risemap.cn/purchase/pending-pool`
- Forge 入口：`http://localhost:4422/_console/apps/forge/page/page_purchase_todo_pool`
- 实时证据日期：2026-09-15，内置浏览器 DOM 与桌面首屏截图。
- 设计状态：`review_required`。当前 RISEMAP 租户没有待采购记录，批量动作的提交结果仍需同材料复核。

## 逐页原型

- 主原型：`task_workspace`
- 参考页面：`project-task-workspace.page.ts`
- 页面职责：采购人员把审批通过的申请明细分配给供应商，随后转成询价或采购订单，并保留申请行来源和剩余数量。

## RISEMAP 已观察事实

- 首屏标题为“采购待办池”，说明为“集中处理待执行采购需求，跟踪供应商分配与采购进度”，右侧存在“下一步操作 询价管理”。
- 页面有“待办列表”和“分组视图”。无勾选记录时，批量创建订单、批量生成询价单、智能拆单、指定供应商、暂缓和关闭均为禁用状态。
- 工具栏包含导出、任务、刷新、搜索、状态、优先级、申请部门、日期范围、“仅未下单”“仅我的”“异常记录”和分页。
- 当前列表可见列为池编号、来源单号、行号、申请人、申请部门、项目/工单、物料编码、物料名称、型号、规格、单位、申请数量、已锁定、已下单、剩余可下单、建议供应商、采购分类、需求日期、申请时间、优先级、状态和负责人。
- 当前租户为空态，因此分组规则、智能拆单、批量动作弹窗字段、成功反馈和状态变化尚未从 RISEMAP 成功办理。

## Forge 首屏与动作

1. 采购模块面包屑、页面标题和下一步询价入口。
2. 待办列表/分组视图。
3. 批量创建订单作为选中记录后的主动作；询价、指定供应商、暂缓和关闭为并列批量动作。
4. 搜索、状态、优先级、“仅未下单”和“仅我的”只筛选当前工作区。
5. 列表保留申请头、申请行、数量和供应商来源；来源单号可回到采购申请。
6. 底部提供操作说明，并明确尚未验证的拆分边界。

## 数据与阻断

- 采购申请审批通过时按申请明细生成采购待办；每条待办保存申请头、申请行、数量、供应商建议、负责人和需求日期快照。
- 没有物料明细的申请不能提交审批；已经生成待办的申请不能重复生成。
- 未勾选记录时所有批量办理动作禁用。
- 指定供应商必须选择启用供应商；创建订单必须填写供应商、目标仓库、期望到货日期和付款条件。
- 已关闭、已下单或没有剩余数量的待办不能创建采购订单。
- 关闭要求填写原因，并把剩余数量置零。该操作使用标准二次确认，属于 Forge 产品安全决策。

## Forge 决策与未决项

- 当前版本只支持整条申请明细生成订单；部分数量拆分和智能拆单保持未实现，不包装成可办理结果。
- 采购订单先保存为草稿，并保存来源采购申请和申请明细；申请仍保持已通过状态，后续按既有订单审批、到货、检验和入库链办理。
- “批量生成询价单”在询价页面独立实现前仍是下一批缺口，不能据此称为采购待办池完整闭环。
- 审批到待办的写入为顺序写入；并发审批和中途失败恢复尚未证明。

## 验收材料

- 内置浏览器：RISEMAP 桌面空态；Forge 桌面与窄屏、无选择禁用、分组、指定供应商弹窗、必填阻断、订单弹窗、提交反馈、来源跳转和操作后回读。
- API：申请头、申请行、审批记录、待办来源、数量和状态一致；重复审批与无明细申请被阻断。
- 持久化：独立 SQLite 完整停服重启后回读同一待办、来源和后续订单。
- 工程门禁：`pnpm typecheck`、`pnpm validate`、`pnpm build` 与页面精修清单检查。
