## 阶段 1 验证边界

Forge 定向验收覆盖以下行为：

1. 创建 `CABINET_OTC` 项目类型。
2. 拒绝计划结束日期早于开始日期的项目。
3. 从客户动作建立待执行项目，并自动把负责人加入项目团队。
4. 无计划也允许开始执行，与本次 RISEMAP 实际行为一致。
5. 关联合同后自动带入全部非草稿、未取消订单；重复关联只刷新，不重复创建。
6. 暂停和恢复不丢失合同金额及关联。
7. 重复开始被拒绝，匿名读取和动作调用被拒绝。
8. 完整停服后从同一 SQLite 回读项目类型、项目、成员和合同/订单关联。

阶段 1 的客户立项、项目状态和订单关联浏览器动作均已通过。`PRJ-2026-002` 是同客户、类型、负责人和周期的界面验收记录；主 OTC 链仍使用 `PRJ-2026-001`，避免重建已有关联和计划。项目工时、费用、交付包和验收属于后续阶段，不能由本阶段结果外推。

## 阶段 3 执行验证边界

1. “项目计划确认”和“召开项目启动会”更新为 100% 时，自动写入进行/完成状态及实际开始、完成日期。
2. “确认项目范围与边界”更新为 50% 时，自动保持进行中并写入实际开始日期；显式延期状态可保留 50% 进度。
3. 阶段按直属非阶段工作项简单平均并取整，`100/100/50` 回算为 `83%`，阶段状态不随进度自动改变；计划按全部非阶段工作项同口径回算为 `83%`。
4. 同一任务持久保存两个前置项，浏览器详情同时显示“项目计划确认”和“召开项目启动会”。多值 lookup 关闭无意义的反向关联列表，避免数据库把 JSON 数组误作单值等值查询。
5. 日报覆盖今日完成内容、完成度、阻塞、协助、预计日期变化、调整日期和附件字段；预计日期声明变化时必须填写新日期。
6. API 与浏览器各提交一条日报；浏览器成功提示、关联列表、日报详情、API 回读及再次停服重启均通过。
7. 附件字段保留 RISEMAP 的单个附件 20MB 页面提示，本阶段未上传真实附件，不能声称附件大小服务端限制已验证。

## 阶段 4 正式 BOM 验证边界

1. 标准 BOM 草稿提交时按四个物料节点计算物料种数 `4` 和未税成本 `14442.48`，审批通过后 BOM 与五个结构节点同时进入已生效。
2. 已生效结构的数量字段由条件只读规则保护；直接修改请求返回成功但明确丢弃该字段，持久值不变。
3. 已生效标准 BOM 可派生项目 BOM，并复制根节点和四个物料节点；项目、客户、来源版本及成本快照随记录保存，同一项目存在有效或待处理项目 BOM 时阻止重复派生。
4. 已生效标准 BOM 可复制为独立 `V1.1` 草稿；评审退回后恢复可编辑，重提同意后可填写原因失效。
5. 提交、同意、退回、复制与失效均保存独立审批日志。浏览器项目 BOM 保存了提交与同意意见，页面显示生效时间和评审人。
6. 本阶段没有在 RISEMAP 远端保存新的项目 BOM。缺料分析、图纸关联、版本替代、归档/删除、BOM 对比、真实附件、导入导出和生产引用锁定不在已证明范围。

## 阶段 5 缺料分析验证边界

1. 仅已生效 BOM 可分析，匿名调用及非正计划数量被拒绝。
2. 零库存分析精确复现 RISEMAP 的 `0% / 4 / 4 / 0 / 14442.48`；库存通过已审批期初入库进入库存余额，没有使用调用方传入的库存数字。
3. 计划数量为 `2` 的 API 分析得到 `60%` 和 3 个缺口；浏览器改为 `1` 后重新分析得到 `80%` 和 1 个缺口，只有 `RM-HMI-700` 缺 `1`。
4. 每次分析保存新的摘要和逐项明细，早期零库存快照不随后续入库或重新分析改变。
5. 完整停服重启后，API 和专用 BOM 工作台均能回读最后一次浏览器分析。
6. RISEMAP 当前对照页面未出现生成采购申请或采购订单的动作。本阶段不实现采购转换，也不证明库存预留、并发订单分配、生产缺料待办或补料闭环。

## 阶段 6 缺料采购验证边界

1. 同材料供应商先提交审批并通过；未审批供应商生成采购订单会被拒绝。
2. 零库存缺料快照生成 4 行采购明细，数量 `1 / 1 / 2 / 1`，总数 `5`，含税总额 `16320.00`；每行保留 BOM 和缺料快照来源。
3. 同一缺料快照不能重复生成有效订单，订单审批意见必填，重复审批不会重复产生通知。
4. 订单审核只生成 1 张订单级待到货通知，并以 4 条通知明细保留物料计划数量；通知仓库可以为空。
5. 浏览器订单另用计划数量 `3` 的缺料快照办理。早期整数 SKU 价夹具为 `33260.00`；当前按 RISEMAP 四位含税行单价和逐行两位小计重放为 `33260.02`。

## 阶段 6.1 多物料到货验证边界

1. RISEMAP 同材料表单一次带出 4 条订单物料，并确认到货日期、供应商、采购订单、每行数量和仓库为必填；保存草稿与提交待检是两个独立动作。
2. Forge 草稿保存 4 行但不增加通知或订单到货量；提交草稿后才进入待检验，并逐行、逐头累计一次。
3. 超过通知行剩余数量、重复或无效通知行、缺仓库、匿名调用和满额后再次到货均被拒绝。
4. API 基准精确回读 4 行、5 件、未税 `14442.48`、含税 `16320.00`；没有自动创建检验单。
5. 浏览器独立办理 `ARR-2026-0002`，4 行、8 件、含税 `33260.02`，并保存物流单号与电源批次。
6. 完整停服重启后，到货登记头、4 条明细、通知和订单累计均按原 ID 回读；浏览器刷新状态仍为待检验。
7. RISEMAP 远端尚未提交该登记，因此逐物料待检实体、检验单生成与免检分流仍待下一阶段实测。

## 阶段 6.2 逐物料检验验证边界

1. 每条到货物料生成一条待检记录；一条待检记录只能生成一张检验单。
2. 检验单逐项保留到货、采购、供应商、仓库、SKU、批次和数量来源，支持全检与抽检两种显示方式。
3. 合格数量限制在 0 至总数量之间，检验结论必填；不合格数量由系统计算，结果自动分为合格、部分合格或不合格。
4. 前三条检验完成时整张到货登记仍为检验中，第四条完成后才进入已检验。
5. API 基准覆盖 4 张检验单，分别验证合格、部分合格和不合格；检验结束不生成采购入库单。
6. 浏览器为 `RM-HMI-700` 生成并完成 `IQC-2026-0005`，总数 3、合格 2、不合格 1；同库重启后页面和 API 均保留原结果。
7. RISEMAP 同材料到货尚未获准提交，实际待检记录生成时机、检验规则和免检分流仍标为待远端复核。
6. 完整停服重启后，页面和 API 都能回读供应商审批、两张已审核订单、各自审批日志及每单一张多明细通知。
7. 本阶段没有登记实物到货，也不证明检验、入库、库存增加或应付确认。旧单物料登记动作与新证据冲突，已隐藏并阻断，下一阶段重新实现。
