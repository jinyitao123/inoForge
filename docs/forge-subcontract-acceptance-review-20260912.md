# 委外样板独立验收审查

审查日期：2026-09-12  
审查基线：Forge `main`，提交 `22fdf28`
验收范围：`SC-ORDER-001` 的一条回厂批次，从异常处置到委外对账和应付生成。  
验收原则：真实页面操作、真实来源关系、同一 SQLite、完整停服重启；健康检查、构建和孤立 API 只作为辅助证据。

## 判定

**当前样板在“回厂批次 → 不良处置 → 对账 → 应付”的范围内条件通过。**

条件是：该结论只覆盖已实际办理的批次和动作，不代表整张订单完成，也不代表 RISEMAP 尚未成功办理的行为已经复刻。样板可以作为后续 RISEMAP 复核和委外剩余功能修补的基线，但暂不推广到采购、生产其他功能、销售或财务其他功能。

## RISEMAP 对照边界

已使用的 RISEMAP 事实材料：

- RM-087 委外对账入口、待对账池、供应商/订单/回厂批次聚合、状态和阻断呈现。
- RM-093 委外对账单的账期、费用构成、应付、关联应付、来源行和状态字段。
- 应付金额首版按“加工费 + 补料 − 扣款”呈现。

仍需 RISEMAP 复核：供应商确认、内部审核与供应商确认的分离关系、部分结算/重开/拆分、差异关闭、赔偿扣款来源、付款关联和订单关闭条件。以上行为在 Forge 中只能称为工程实现或待复核，不能称为 RISEMAP 已复刻。

| 目标域 | 当前结论 |
| --- | --- |
| 委外剩余功能 | 可以继续按同一门禁修补，优先补退料、供应商确认、差异和权限边界 |
| 采购 | 暂不推广；需独立菜单、岗位任务和真实采购闭环验收 |
| 生产 | 暂不推广；委外样板通过不等于组装、图纸或生产入库通过 |
| 销售 | 暂不推广；销售链有独立残余缺口和 RISEMAP 待复核行为 |
| 财务 | 暂不推广；委外应付只证明来源生成，不证明完整资金、发票和付款闭环 |
