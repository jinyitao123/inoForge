审查日期：2026-09-12

验收范围：`SC-ORDER-001` 的一条回厂批次，从异常处置到委外对账和应付生成。  
验收原则：真实页面操作、真实来源关系、同一 SQLite、完整停服重启；健康检查、构建和孤立 API 只作为辅助证据。

## 判定

**当前样板在“回厂批次 → 不良处置 → 对账 → 应付”的范围内条件通过。**

条件是：该结论只覆盖已实际办理的批次和动作，不代表整张订单完成，也不代表 RISEMAP 尚未成功办理的行为已经复刻。样板可以作为后续 RISEMAP 复核和委外剩余功能修补的基线，但暂不推广到采购、生产其他功能、销售或财务其他功能。

3. NCR `NCR-SR-API-20260912-001-01` 配置为退货 1 件，提交审批、审核通过并执行。
4. 订单上下文回读 NCR“已执行”，对账入口恢复。
5. 对账池选择 `SR-API-20260912-001`，填写账期 `2026-09-01 至 2026-09-12`，生成 `REC-UI-20260912-001`。

12. 在当前 `main` 上用独立端口 `4450` 和全新 SQLite `/tmp/forge-subcontract-main-rerun-20260912-v2.sqlite` 重跑 `pnpm acceptance:subcontract-one-db-chain`，连续阶段 `order → issue → supplier_signoff → receipt → inbound_confirm → ncr_disposition → reconciliation → payable` 全部通过；随后完整停服、同库重启，运行 `pnpm acceptance:subcontract-one-db-restart` 按原单据 ID 回读通过。该次复跑只更新 Forge 本地证据，不改变 RISEMAP 数据。

## RISEMAP 对照边界

已使用的 RISEMAP 事实材料：

- RM-087 委外对账入口、待对账池、供应商/订单/回厂批次聚合、状态和阻断呈现。
- RM-093 委外对账单的账期、费用构成、应付、关联应付、来源行和状态字段。
- 应付金额首版按“加工费 + 补料 − 扣款”呈现。

仍需 RISEMAP 复核：供应商确认、内部审核与供应商确认的分离关系、部分结算/重开/拆分、差异关闭、赔偿扣款来源、付款关联和订单关闭条件。以上行为在 Forge 中只能称为工程实现或待复核，不能称为 RISEMAP 已复刻。

## RM-086 三方互审增补

产品审查：RM-086 是“委外退料”独立岗位入口，不应直接暴露库存余额对象；页面必须显示关联订单、供应商、退料原因、退料结果和下一步。确认退料与仓库入库是两个业务节点，不能合并成一次立即扣账。

工程审查：复用 `forge_subcontract_stock_balance` 和 `forge_subcontract_stock_ledger` 作为执行底座，新增退料头、明细、待入库单和日志保持来源可追溯；退料仅允许甲供料订单，数量按当前在外余量校验。当前顺序写入未升级为事务或补偿，供应商外部账号确认未实现。

质量审查：已覆盖草稿不动库存、超量阻断、确认后待入库、入库后余额/累计/流水、同一 SQLite 停服重启回读，以及内置浏览器列表和新建表单。尚未覆盖 RISEMAP 线上成功写入、真实多角色账号和赔偿扣款联动。

三方结论：**RM-086 可作为 Forge 受控本地样板纳入委外基线，但不能宣称 RISEMAP 行为已完全复刻，也不能单独触发向其他业务域推广。**

## 推广判定

| 目标域 | 当前结论 |
| --- | --- |
| 委外剩余功能 | 可以继续按同一门禁修补，优先补退料、供应商确认、差异和权限边界 |
| 采购 | 暂不推广；需独立菜单、岗位任务和真实采购闭环验收 |
| 生产 | 暂不推广；委外样板通过不等于组装、图纸或生产入库通过 |
| 销售 | 暂不推广；销售链有独立残余缺口和 RISEMAP 待复核行为 |
| 财务 | 暂不推广；委外应付只证明来源生成，不证明完整资金、发票和付款闭环 |
