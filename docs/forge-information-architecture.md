# Forge 信息架构与分组规则

更新于 2026-09-09。本文件约束完整复刻期间的导航、对象归属和页面层级。RISEMAP 的现有分类是重要证据，但 Forge 的信息架构以用户办理业务为主线；底层对象数量不直接等于一级菜单数量。

## 页面层级约束

1. 一级业务区表达业务责任域，不放单据状态或技术对象。
2. 二级分组表达稳定任务簇，例如“客户档案”“供应商配置”“BOM 管理”。
3. 三级入口指向用户可直接办理的列表、看板、工作台或设置页。
4. 联系方式、银行账号、单据明细、BOM 节点等依附对象，正式体验优先以内嵌子表或详情页签出现；当前 ObjectStack 通用列表只承担模型验证，不能据此认定最终交互完成。
5. 配置项靠近其消费业务，同时在“组织与系统”保留统一治理入口；同一配置只有一个权威定义。
6. 菜单按权限隐藏时，接口、搜索、导出与 AI 工具必须使用相同权限边界。

## 证据和完成声明

每个入口分别记录 `runtime_observed`、`frontend_static`、`published_guide`、`published_example`、`release_note` 和 `forge_verified` 来源。静态前端可支持字段与布局草案，公开说明可支持流程假设，只有运行结果可以证明保存、状态变更、权限和跨单据联动。

当前四个已实现业务区以基础资料为主；“客户与销售”已增加报价、合同、订单的可持久化基础单据链，但审批、转换和下游履约尚未实现。其余一级业务区列入完整目标，不因导航尚未出现而移出范围。
