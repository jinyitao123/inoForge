## 商机到报价的正式关联（2026-10-01）

当前报价模型以 `forge_quotation.opportunity_id` 引用商机；新建报价页只从认证 ObjectStack 数据读取接口列出当前销售本人有权读取的商机，并按所选客户过滤。`sales_quotation_draft_create` 在写入前重新校验商机属于当前组织、报价经办人本人且关联同一客户，再写入关系及只读展示兼容字段 `opportunity_name`。直接按客户新建报价仍可不关联商机。报价转合同、合同转订单继续用现有 `quotation_id` 串接，不复制一套商机字段或替换正式动作。

本次源码 harness 仅验证关系字段的写入、权限范围拒绝和旧的无商机输入兼容；页面 source parse 与既有销售报价静态检查不构成正常浏览器办理或同一 PostgreSQL 读回。报价、合同和订单的完整 OTC 链保持待 Root 按本轮材料进行正常页面验收，历史走查和验收结论按原记录保留。

## 2026-10-01 线索转商机输入映射

RISEMAP 线索转化弹窗观察到商机名称、预计金额、预计关闭日期、商机阶段和备注；客户名称来自当前线索公司。Forge 原弹窗只把金额和日期发给 Action，名称仍被 Action 硬编码，阶段显示为“初步接触”但 Action 实际写入“需求确认”，备注没有输入控件。

当前实现将商机名称、金额、预计关闭日期、商机阶段和备注一并提交到正式 `sales_lead_convert_to_opportunity` Action。名称、阶段、预计成交日期和备注均绑定 `forge_sales_opportunity` 字段元数据；阶段下拉及默认值直接读取 `SalesOpportunity.stage` 的选项和默认值。客户仍取线索公司并经既有客户转换逻辑创建或关联，不把它伪装成可编辑 Action 参数。线索原备注继续按原规则写入商机 `description`；转化弹窗的备注写入商机 `remarks`。

转化 Action 按模型阶段选项和严格 `YYYY-MM-DD` 日期验证写入；同一输入重放仍返回既有关联，不重复建客户或商机。缺少新参数的旧调用仍以线索公司名加“项目商机”、模型阶段默认值和空商机备注执行，并兼容已有只记录金额/日期摘要的转化。

源级回归覆盖字段到 Action 的实际载荷映射、模型阶段选项、字段保存、坏日期/阶段/空名称前拒绝写入、同输入重放以及旧签名回读。该回归和类型检查不替代 Root 后续执行的安装版 UI 操作及独立对象读回；本节不把它们记为本轮业务闭环通过。
